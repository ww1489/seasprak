# 第 8 章：上下文工程

状态：按 M08 小标题与设计精华 review 修订的 PRD；本章规定上下文行为与验收，尚不是实现成果。对应教程 [M08 上下文工程](https://dg-ai-notes.pages.dev/modules/ch08-context-engineering/)。

本章是“每次模型调用到底看见什么”的唯一规格来源。消息类型归[第 6 章](06-messages.md)，压缩算法归[第 9 章](09-compaction.md)，扩展版本归[第 11 章](11-extensions-workflows-access.md)。

## 1. 执行摘要

### 1.1 问题与方案

完整历史、项目规范、skill 正文和工具输出都可能超过模型窗口；任意 middleware 各自增删消息，还会让同一任务先后看到不同规范，或将内部提示当成用户历史保存。

建议将“用户历史”与“模型输入投影”分开，由一条有固定顺序的上下文管道组合历史、当前输入和冻结的能力资源。工具向模型提供有界预览和可用的续读入口；历史保存与原始内容引用分开处理，预算覆盖最终请求，不仅计算聊天文本。

### 1.2 成功标准

- 相同历史版本、资源版本、模型配置和任务输入，生成相同的上下文清单；动态时间等变量必须显式列入输入。
- 每次模型请求均通过工具关联校验和预算检查；所有截断、排除与摘要均有来源及原因。
- 同一 Trace 的 steering、follow-up 及 resume 使用同一资源 generation，不因磁盘更新改变旧资源；下一独立 Trace 才采用新 generation。
- 原始历史不被上下文过滤或压缩覆盖；上下文诊断不泄露模型凭据。

### 1.3 两层防护与四项互补机制

| 位置 | 机制 | 解决什么问题 | 触发与归属 |
| --- | --- | --- | --- |
| 输入侧 | 工具输出截断 | 单次文件、日志或搜索结果过大 | 输出进入上下文前；M05 执行，本章规定预览和续读 |
| 输入侧 | 系统提示与资源组装 | 模型需要知道当前能力和项目规范 | 按当前快照构造模型输入；基础指令、来源块及 skill 索引见 4.3～4.4 |
| 历史侧 | Compaction | 当前路径的长对话挤满窗口 | 预算、经确认的溢出或手动触发；算法和提交归 M09 |
| 历史侧 | 分支摘要 | 切换路径后丢失其他分支的探索结论 | 显式选择携带离开分支的摘要；范围与保存归 M09/M10 |

四项机制各有用途：单条输出仍需截断，历史压缩不能替代它；项目规范和摘要是增加必要信息，预览和过滤是减少无关体积；可能用到的 skill/大产物通过工具按需加载，不提前塞入所有正文。无需为这张概览新增四套管理器。

### 2.3 正常、异常与边界轨迹

**正常**：用户提交修复任务 → 绑定 generation G3 与规范快照 → 模型只看到 skill 索引 → 加载 G3 的测试 skill → 命令产生大日志 → 保存完整产物并返回尾部预览 → 重新预算 → 模型按分页接口读取所需日志后继续。

**异常**：完整输出保存失败 → 工具报告“预览已截断，完整产物不可用”及原调用实际执行结果 → 不发布虚假可读引用、不自动重跑有副作用命令；由任务依据现存证据继续或明确失败。

**边界**：Trace 等待人工输入时 skill 更新到 G4 → 恢复保留原 traceId、创建新 executionId，仍用 G3 → 当前 Trace 的 follow-up 也用 G3 → 下一独立 Trace 才采用 G4。必需输入超预算先返回缺口，不以追加 follow-up 绕过。

非目标：通用 RAG 平台、向量数据库、自动把整个仓库塞入提示词、保证模型一定遵守所有文本指令、以 XML 标签充当安全隔离。

## 3. AI 系统需求

### 3.1 单一上下文处理顺序

以下是逻辑阶段，不要求一阶段对应一个 Go 类型，也不要求重写 Eino 模型循环。

| 顺序 | 处理 | 不变量 |
| --- | --- | --- |
| 0：生产时 | 工具完成输出保存与有界预览；产品消息独立提交 | 原工具状态、toolCallId、产物引用不因后续压缩改变 |
| 1：定范围 | AgentSession 确定 traceId、当前 Turn/invocation、generation、历史叶子、本轮模型配置及已验证工具选择；L1 按 M04 解析思考和输出选项 | traceId 确定完整运行归属；预算使用实际生效档位与限制；未消费输入不提前加入上下文 |
| 2：取历史 | SessionManager 提供所选分支及生效摘要对应的历史，合并 M03 已消费的新输入；按 inputId/messageId 去重 | 已受理但未消费的输入仍在队列；不混入其他分支/子 Agent，不重复追加已进入历史的输入 |
| 3：transformContext | 在 AgentMessage[] 上选择、过滤和缩减旧工具预览，加入冻结的项目规范、skill 与允许的结构化贡献；系统指令单独准备 | 保留原始输入关联和派生来源；不覆盖授权原文，不改原历史或权限；未闭合工具调用不可删除 |
| 4：convertToLlm | 按 M06 将处理后的内部消息转换为 []*schema.AgenticMessage，再组装 system 与工具选项 | 保留标准内容块，自定义消息按明确规则转换；不再次注入业务贡献，不因 user role 误判工具结果为人类输入 |
| 5：全量预算 | 计算完整请求与输出预留；不足则向第 9 章申请压缩并重新从第 2 步构造 | 压缩次数有上限；固定内容超限不循环压缩历史 |
| 6：最终校验 | 检查角色映射、工具调用对、媒体能力、引用可用性与最终预算 | 失败不发送模型；后续 provider 转换增加的开销仍须被覆盖 |
| 7：提交调用 | 保存诊断清单并交给模型适配层 | 不在此阶段接纳新消息、改 generation 或再追加未计量提示 |

工具实现、schema 和资源版本固定于 generation；本轮选择可在 M05 允许的边界变化。变更时工具定义、使用说明、skill 加载器可用性与预算采用同一集合；普通隐藏工具不继续出现在“可直接调用”的说明中。已认证的原生延迟工具单独表达为可检索能力，不冒充已直接开放。retry/resume 使用所关联 Turn 的选择，不能临时读取全局最新清单。

系统/规范/skill 可以通过匹配 Agentic 类型的 Eino 扩展点组装，但外部可观察行为必须等价于此顺序。预算不足时从原始结构化历史选择摘要来源，再重新执行步骤 2～6；不是在拍平后的模型消息上补一条相互独立的压缩管道。不得同时启用多个互不知情的自动压缩器。

本节构造主执行模型的输入，不作为 Auto 的授权原文来源；审核按 M12 读取受信原始输入、已生效限制和委派关系。投影/压缩不能把事实提升为授权，也不能因为主模型暂时看不到某条限制就让审核忽略仍有效的限制。

例如工具执行期间受理了 follow-up F：当前模型输入和当前压缩候选均不含 F；只有 M03 外层将 F 标为 consumed 后，它才以一条用户消息进入后续输入。请求重建从已提交历史或本次消费集合取得这条消息，不能两处各追加一次。

### 3.2 预算和评估

预算判定建议为 `estimatedInput + reservedOutput + safetyMargin <= contextWindow`。`estimatedInput` 包括工具及媒体；最大输出还必须满足模型独立输出上限。所有数量区分实测 usage、模型专用估算与通用近似，不能将字节数标成真实 token 数。

思考模式与输出限制先按 M04 映射为有效选项，再参与本章预算。思考和答案共用响应上限时，reservedOutput 包含两者，不重复相加；存在独立限制的模型按已认证口径计算。模型/思考档位改变需重算，适配器不得在本章校验后悄悄扩大 maxTokens。调用后发生的服务端溢出由 M04 识别并交 M09，不能以估算偏差直接认定任意模型错误都是溢出。

有可信 usage 时仅在同一模型、投影版本和工具集合下增量估算；压缩、模型切换、工具集合变化后重新建立基线。中英文、emoji、图片、超长单行和零 usage 响应均进入固定测试集。模型窗口未知时要求配置明确的保守上限，不自行宣称不限长。

确定性评测使用假模型捕获最终请求，检查顺序、版本、预算及原始历史不变。真实模型评测检查是否读取了正确 skill、是否能通过引用找回错误日志；成功率及成本门槛待统一评测集确定，本章不虚构基线。

### 3.3 为供应商前缀缓存保持稳定输入

M04 负责缓存协议，本章负责可供复用的内容。相同逻辑上下文可重复生成相同前缀，并不意味着服务端一定命中；反过来，正确设置缓存字段也不能补救每一轮都被改写的提示词。

- 固定的系统指令、项目规范与工具声明按稳定顺序组织；同一 generation 内名称、描述和 schema 不因重复装配而漂移。实际请求的 system/tools/messages 位置遵循 L1 的供应商协议，不强行把工具 schema 塞进聊天消息。
- traceId、turnId、诊断时间、用量计数等运行 metadata 默认留在请求上下文或事件 metadata，不嵌入模型可见的稳定前缀。模型确实需要的时间/状态等动态内容明确放在合适的输入位置，正确性优先于缓存。
- 已提交历史保持内容与顺序，后续输入、工具结果按消息因果关系追加；不能为提高缓存率重排工具结果、复用错误分支或保留已撤销指令。
- 参考 DSH，受信安全策略变化以带来源的完整当前状态追加在保留历史之后，不回写稳定 system 前缀。它是可变运行策略的说明，区别于冻结的 skill/工具资源；策略收紧仍即时约束后续操作。内部审批/审核记录不自动成为模型消息，摘要也不能把这些事实转成人类授权。
- skill 默认索引与按需正文来自同一任务快照。加载正文后避免每次将相同正文重复插入历史前端；需要重新注入时由统一管道记录其来源和边界。不能每轮把变化的“已加载列表”写进静态 system 开头而不评估代价。
- 压缩、分叉、模型/工具切换确实改变上下文时，应重算内容摘要、投影版本与缓存适用性；合法共同前缀可由供应商继续复用，显式缓存句柄或有状态续接 ID 则由 L1 按 M04 校验，不能无条件沿用。

例如两次调用的逻辑输入是“相同指令/工具 + 历史 H + 用户问题”和“相同指令/工具 + 历史 H + 用户问题 + 工具往返”。旧 H 的内容和顺序可保持稳定；若在第二次调用的 system 开头添加新的随机 executionId，就可能失去这部分前缀复用。最终请求的具体块结构仍由 L1 决定。

AgentSession 向下提供不透明的稳定缓存作用域与资源版本，Agent 提供来源/内容摘要；L1 负责厂商缓存参数和 usage 归一化，SessionManager 仅保存相关诊断。详细协议边界见 [M04](04-model-access.md#45-供应商前缀缓存与续接契约)。

## 4. 技术规格

### 4.1 分层与数据契约

L1 接收最终模型请求及能力约束；L2 的 Agent 负责上下文贡献、投影和最终校验；L3 的 ResourceLoader 发现并读取规范和 skill 候选资源，ExtensionRegistry 管理工具、子 Agent、Workflow 的声明注册及候选校验，AgentSession 在安全边界选定不可变快照与历史范围，SessionManager 提供所选分支的历史来源。产物授权由应用装配方注入的策略负责，CreateAgentSession 只负责组装这些依赖。L2 通过接口取得上下文输入，不导入 AgentSession、SessionManager、ResourceLoader、ExtensionRegistry 的具体实现或具体存储后端。可内存构造所有输入，以验证没有编码工作区的通用 Agent。命名与职责见[第 2 章](02-architecture-boundaries.md)。

上下文诊断建议包含 `traceId/executionId/invocationId`、目标 Agent、generation、历史叶子 `entryId`、投影版本、模型配置标识、来源清单及内容哈希、各预算分项、被排除项及原因。默认查询返回元信息，读取正文沿用原资源权限；不把 API key、认证头或所有提示词自动广播到 SSE。

invocationId 是产品生成的主/子调用身份，恢复时保留其对应执行范围；Eino RunPath 只作框架诊断信息，不能作为同名子 Agent 的唯一隔离键。字段语义统一引用 M06/M07。

完整输出使用稳定产物标识，OS 文件路径是后端属性。Windows 原生、Linux、macOS、容器使用同一读取契约；宿主机路径与容器路径不可直接互换。产物的生命周期、不可用状态及历史引用由[第 10 章](10-session-persistence.md)管理。

### 4.2 工具输出：截断、说明与续读

工具先返回真实执行结果，再为模型构造预览；截断不改变退出码、错误类别、调用配对或副作用状态。以下是首个编码配置的默认行为，其他工具通过明确输出策略复用同一契约。

| 输出类型 | 保留策略 | 超长单行与继续读取 |
| --- | --- | --- |
| 文件 read | 在请求的 offset/limit 范围内从头保留完整行，再应用行/字节双上限 | 首个所选行单独超字节上限时，返回“该行过长”的提示及片段读取方法；不把空预览解释为空文件，不无声切断后冒充整行 |
| 命令 stdout/stderr 日志 | 保留最后若干行/字节，优先呈现最终结果；完整日志另存产物 | 最后一行单独超限时可保留 UTF-8 安全的尾部片段，标记部分行、原始大小与完整产物位置 |
| 搜索 grep | 限制命中数量/总字节，再对每条命中行独立限长；保留资源位置和行号 | 长行附截断标记，提供按位置读源文件/片段的入口；不能让一条 minified 代码占满所有命中预览 |
| 自定义结构化结果 | 工具作者声明有界摘要字段和详细结果引用 | 不直接按字节裁剪 JSON 或工具参数，避免形成无效结构 |

搜索单行限长可参考 pi 的 500 字符作为开发者默认值，产品按完整 Unicode 字符计数，UTF-8 字节限制另行计算；不强制把该数字用于所有工具。文件头部完整行、日志尾部部分行和搜索单行预览是三种行为，不能只靠一个统一字符串截断函数猜测用途。文本输入本身编码异常时按工具解码规则报告，不能把既有无效输入和截断造成的损坏混为一谈。

模型可见的截断说明至少包含：保留的行/片段范围、因行数/字节/单行限制触发、是否为部分行，以及如何取得缺失内容。details 可保留完整计数；说明正文也计入 M08 总预算。示意：“已展示第 1～120 行，因字节限制停止；使用当前文件读取工具从第 121 行继续。”使用哪种工具及参数由实际装配能力提供，不生成环境中不存在的命令。

普通文件读取优先引用原资源和续读范围，不要求每次 read 再复制整个文件到产物。源文件已变时续读说明当前版本/变化，不保证将两次读取拼成同一快照；需要稳定历史证据的工具自行保留结果产物。命令日志只有成功保存后才报告可读产物。产物失效、保存失败或加载器缺失时明确标为不可用，不建议重新执行有副作用命令来“补日志”。shell 的后端私有临时路径需先按 M12 导出为同 Session 可访问的真实产物再提供续读方法；不能让文件工具从宿主同名路径补读。

行级 offset 无法处理超长单行时，编码配置需要可用的有界片段读取能力，允许复用已有读取工具，不要求新增工具名称；Windows、Linux、macOS、容器都通过同一语义提供，不能将 bash/sed 作为未声明前提。每次续读仍受工具输出及完整模型预算约束。原产物访问权限、生命周期及不可用状态继续由 M05/M10 管理。

### 4.3 系统提示词的组装结构

以下是逻辑组装顺序，不是要求另写一套提示词引擎。应用可自定义通用 Agent 人设；实际工具说明与模型工具 schema 来自同一有效能力集合，不能沿用 pi 的编码角色或提示调用未装配工具。

| 顺序 | 内容 | 替换、追加与来源规则 |
| --- | --- | --- |
| 1 | 基础角色和应用指令 | 使用开发者提供的默认值；custom system prompt 替换这一部分，不暗自取消后续明确启用的项目规范、skill 或安全执行策略 |
| 2 | 实际工具使用说明和通用 guidelines | 仅列当前可见工具的简要用途和必要使用约定；完整工具 schema 仍通过工具选项传递，不重复塞进正文 |
| 3 | 显式追加指令 | 追加到当前基础内容；保留来源，不把 append 当成替换全部系统指令 |
| 4 | 项目规范块 | 全局→获准祖先从外到内→当前目录；每份规范有模型可见的来源位置、作用域和内容边界 |
| 5 | 可自动使用的 skill 索引 | 仅元信息及加载方法；不预先注入全部正文，具体见 4.4 |
| 6 | 工作区及必要动态信息 | cwd/逻辑工作区在适用时明确提供；时间仅在需要时作为显式输入，避免每 Turn 改写静态前缀 |

默认规范发现按同目录 AGENTS.md 优先、无该文件时 CLAUDE.md；大小写兼容名及其他名称只按已声明的固定优先级识别。文件/资源使用规范化身份去重，不因同一路径的别名重复注入；读取只在配置的发现根内进行。此规则是本产品的简化选择，不承诺复制 pi 所有 override/worktree 发现细节。

项目规范用 XML 或等价的明确分隔块表达“来源 + 作用域 + 正文”，这些信息必须出现在模型实际输入中，不能只存进诊断清单。相同字段按固定格式转义/分隔，防止来源路径破坏结构。层级递进用于解释通用约定与局部细化；冲突不得靠来源名称抬升权限，工具授权仍在执行边界判断。

上述内容可形成 system 指令或由适配器保留同等来源语义的内部上下文贡献，但每一项只组装一次；已加载 skill 正文、工具结果、分支摘要按各自消息语义进入上下文，不能每次全部复制到 system。预算、前缀稳定和“不伪装用户原始输入”仍按 3.1～3.3 执行。产品 Session 必须有明确工作区，即使应用显式裁剪文件工具也不能省略绑定。项目发现可由应用关闭或替换为显式指令/内存资源，但不能把工作区必填误解为必须将全部目录内容交给模型。独立 L1/L2 测试可使用替身，产品 SDK 用例仍提供测试工作区。

### 4.4 Skills：先给索引，再用工具加载

每项自动可用 skill 至少给出名称、用途描述、位置或稳定资源 ID，以及其对应加载工具/引用约定。选择其中一个已装配位置展示索引：系统提示或 skill 工具描述；不在两处重复铺开同一清单。只有元信息入 prompt，正文在实际选择并成功加载后进入上下文。

加载器可复用 Eino skill Backend.List/Get，也可以是获准的文件/资源读取工具；名称不必叫 read。没有对应加载能力、无法定位资源或声明仅供显式调用的 skill，不放进“可由模型自动加载”的清单；应用仍可通过单独公开能力报告可用性和原因。必要 skill 无法加载时明确失败，不以索引描述冒充已经阅读正文。

这里的懒加载指正文按需进入模型上下文，不承诺发现阶段只读取文件元信息；ResourceLoader/backend 可以为校验和固定版本读取完整文件，仍不把所有正文预付为模型 token。

skill 内的相对引用以 SKILL.md 所在目录或资源基址解析，不按进程当前 cwd 猜测；实际读取继续检查资源访问范围。索引、正文和声明的配套指令资源属于同一 generation；运行期业务文件按真实读取结果记录，不为了 skill 快照而冻结整个工作区。

同一有效 skill 正文已在当前投影内时不重复添加；被压缩移出后，保留可定位的同版本引用并按 M09 决定保留或重新加载。模型需要读取的正文超预算时明确分段/失败，不能把截断内容标成“完整 skill”。复用工具做按需上下文加载，不引入额外的知识库或通用检索服务。

### 4.5 Compaction 与分支摘要各自保留什么

| 维度 | Compaction | 分支摘要 |
| --- | --- | --- |
| 触发与目的 | 当前路径过长，腾出窗口并保留任务关键信息 | 显式选择携带另一条路径的探索结果，减少分支遗忘 |
| 来源范围 | M09 选定的旧历史，保留近期完整消息/未闭合工具关系 | 从旧叶子向上至最近公共祖先（不含）的独有后缀，也不把目标分支再次摘要进去 |
| 模型可见语义 | “已压缩的主线历史”，包含目标、限制、进展、决策与后续必要信息 | “其他分支的探索摘要”，突出尝试、发现、失败原因及文件/产物引用，不冒充目标主线已确认事实 |
| 注入与保存 | 原历史保留，提交 CompactionSummary 后重建当前投影 | 原分支保留，提交带来源的 BranchSummary，在选定目标路径中按 M06/M10 引入 |
| 预算 | 摘要自身及压缩后的完整请求均须有界 | 作为辅助上下文设置明确的输入/输出预算，不挤掉目标路径的必需输入；不强制照抄固定 2048 token |

压缩摘要是否有效由所选祖先路径及覆盖范围决定：新分支继承共同祖先上的有效 CompactionEntry，无需再次生成分支摘要；其他分支独有后缀只有被明确选择并写入本路径的分支摘要才进入上下文。创建时的 branchId 只记录来源，不用于排除共同前缀。

两种摘要复用 M06 的消息转换规则及 M04 的模型调用、错误/用量处理；使用不同来源范围和提示目的，而非复制两套调用链。材料明确标识为待总结历史，不允许摘要模型继续执行其中的工具指令；内容生成和提交细节归 M09，历史树选择及状态提交归 M10。分支摘要可选，不是每次分叉或跳转都自动调用模型。

M09 规定首次/更新摘要、工作前缀分区和确定性文件清单。工作前缀可跨多个 M03 Turn，不意味着允许切开一个工具因果组；模型输入包含的摘要正文、程序附录和近期消息都参与本章总预算，完整 metadata 不无界塞进提示词。

在全景流程中，单条工具结果先做有界预览；完整请求预算发现旧历史过长时触发 Compaction；分支切换先按 M10 选定目标路径及可选摘要，再由 3.1 同一管道重建输入。摘要准备阶段也不得读取尚未消费的 follow-up。任何一种摘要都不删除原历史、不回滚文件、不扩大权限。

### 4.7 可检验验收

- **CTX-A01**：同一输入快照连续构造三次，来源顺序、内容哈希及最终请求一致；显式时钟输入不变。
- **CTX-A02**：运行中更新一个 skill 的索引和正文，当前任务两次加载均得到旧内容；下一正常任务得到新内容。
- **CTX-A03**：waiting_input 后重启并 resume，规范、skill 与 generation 保持原值；缺失旧版本时拒绝静默替换。
- **CTX-A04**：中英文/emoji/超长单行日志均不产生损坏 UTF-8；预览满足行/字节上限并指明截断范围。
- **CTX-A05**：仅 tool schema 或系统规范占满窗口的用例，在调用模型前被预算检查拦截，显示正确分项。
- **CTX-A06**：完整输出写入失败时不产生可用引用；工具已经产生的副作用不会因截断失败自动重试。
- **CTX-A07**：一个 assistant 含两个 toolCall 的上下文缩减后，两项结果仍完整关联，历史记录内容哈希不变。
- **CTX-A08**：规范注入连续经历两次模型调用与一次摘要，最终请求只含一份有效规范，用户历史不多出合成用户输入。
- **CTX-A09**：SDK 显式提供测试工作区并裁剪文件工具，仍可通过内存上下文完成业务任务；创建产品 Session 缺少工作区时明确拒绝。
- **CTX-A10**：父任务及两个子 Agent 并行准备上下文，各自仅含被委派内容；一个子任务压缩不修改其他作用域。
- **CTX-A11**：切换模型或压缩后，不使用旧 usage 重复触发压缩；未知窗口必须有明确配置才能发出请求。
- **CTX-A12**：Windows/Linux/macOS/容器的同类产物均通过统一授权读取入口取得指定范围，不能跨 Session 任意读取。
- **CTX-A13**：同一有效资源和工具集合连续调用三次，只追加已消费输入与工具结果；最终厂商请求中的合法稳定前缀不变，没有随机 ID、当前时间或重复 skill 正文混入。
- **CTX-A14**：工具 schema 更新、分叉和压缩分别改变对应输入时，资源/投影版本与缓存诊断同步更新；失去缓存命中也不恢复错误历史或旧权限。

- **CTX-A15**：受理 steering/follow-up 后、到达各自消费边界前构造模型请求或摘要，均不含待消费输入；实际消费后只进入一次，预算重建不重复追加。
- **CTX-A16**：同一大文本分别作为 read、命令日志和 grep 结果，验证头部/尾部/命中单行规则；超长首行与末行不混同，路径和行号保留，模型正文含真实可用的续读提示。
- **CTX-A17**：在无 bash 的 Windows 与有 shell 环境读取超长单行，均可通过已装配的有界片段能力继续；工具不存在或原资源已变时明确反馈，不返回虚假完整内容。
- **CTX-A18**：默认 system、自定义替换和追加指令分别组装；基础角色不重复，工具说明只含有效工具，来源分隔可见，项目规范/skill 索引仅一份，日期不被无条件插入静态前缀。
- **CTX-A19**：skill 索引指向可用资源，按说明实际加载；移除加载能力后不再宣称可自动使用；从不同 cwd 加载时相对引用仍按 skill 基址解析，正文来自原 generation。
- **CTX-A20**：同一会话同时具有压缩记录及选定分支摘要，模型能区分主线历史和另一分支探索；来源不重叠、必需目标上下文保留，完整预算通过，原历史不变。

## 5. 风险与待定项

| 项目 | 风险与处理要求 |
| --- | --- |
| 必需内容增长 | 规范、schema、活动 skill 本身可能超过窗口；需要清晰拒绝或用户选择，不能只靠摘要旧历史 |
| 工具输出丢失 | 预览不能代表完整成功证据；必须区分工具执行结果和产物保存结果 |

| Eino 状态回写 | 顺序组合可能把临时规范送进摘要，或在恢复时重复加入；禁止仅凭注释判断，须满足 CTX-A08 |

| 阶段范围 | 本章先固定完整行为契约；最小验证集和后续交付阶段在全系统评审后划分，不在此制定编码计划 |
