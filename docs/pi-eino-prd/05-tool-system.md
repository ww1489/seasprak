# 第 5 章：工具、权限与副作用

状态：完整系统 PRD 讨论稿，2026-09-22 更新。工具方法论依据 [pi M05](https://dg-ai-notes.pages.dev/modules/ch05-tools/) 与本地实现；安全审核、审批审计和沙箱按用户要求参考 DeepSeek Harness。Windows 原生、Linux、macOS、容器均为目标环境。安全策略和实际约束能力的唯一规格见[安全与沙箱补充篇](12-security-sandbox.md)，本章定义它如何进入工具执行过程。

## 1. 执行摘要

### 1.1 问题、方案与成功标准

模型说“调用工具”不等于参数正确、具有权限或实际成功。通用底座必须让文件、命令、业务 API、工作流及子 Agent 使用相同的调用身份、权限判断、结果和恢复边界，并保留每种能力自己的输入输出。

拟定方案：工具定义描述模型可见能力；执行前统一校验、策略和预算；执行器提供真实结果、进度和取消信息；AgentSession 协调 SessionManager 保存可审计记录。普通业务失败可以返回模型纠正；副作用不确定、存储失效和失控执行不得伪装成普通失败后自动重试。

工具整体采用 pi 的分层定义、五步处理、错误反馈、结果双通道及 Operations 思路；安全层采用 DSH 的按调用解析策略、单次批准、独立审计和可替换沙箱后端。两者通过接口组合，保留既定 Agent/AgentSession/SessionManager 分工，不引入 Cordis 或复制 pi 的 TUI。

建议验收门槛：

- 未知工具、无效参数和被拒绝调用的实际执行次数全部为 0。
- 每个被派发的调用都有唯一结果记录或明确的 `outcome_unknown`，并关联原调用。
- 已完成副作用不因模型重试、审批重复提交或断连恢复而再次执行。
- 同一资源的写操作不会无序覆盖；长工具可观察、可取消；不合作的执行器不能阻塞 Session 静默继续写入。

### 1.3 从 pi 提炼的方法论

| 方法 | 为什么这样设计 | 本产品吸收方式 |
| --- | --- | --- |
| 分层递进 | 模型只需工具描述，执行循环需要运行能力，应用才知道资源和展示 | Tool 元信息 → 可执行 AgentTool → 应用 ToolDefinition；优先复用 Eino 接口，保持字段和职责归属 |
| 参数转换完成后校验，再冻结授权 | 格式兼容、输入正确性与许可是不同判断 | 业务转换集中于 prepareArguments；最终校验后冻结，批准后不改参数 |
| 错误作为模型反馈 | 模型可据文件不存在、编辑冲突等信息修正下一步 | 工具给具体原因，框架归一结果；安全设施失效或副作用未知仍需停止/暂停 |
| content 与 details 分开 | 模型工作材料与客户端结构化信息不同 | 模型内容有界，details/产物保留事实；UI 实现不进入执行接口 |
| Operations 注入 | 同一工具语义可用于本地、沙箱、容器和测试替身 | 文件、修改、命令依赖所需的窄能力，不引入巨大环境接口 |
| 并发执行与顺序提交分离 | 工具可先完成先显示，模型历史仍需正确配对 | 顺序准备、受控并发、按请求顺序归并；文件后端补资源串行与版本检查 |
| 明确调用终点 | 异步工具可能返回后仍推送进度 | 结束时关闭入口，结算已接纳进度再发最终结果；观察者不改事实 |

## 2. 用户体验与功能

### 2.1 用户故事与验收

以下 `TOOL-*` 为拟定产品需求。

| 编号 | 用户故事 | 验收条件 |
| --- | --- | --- |
| TOOL-01 | 作为扩展作者，我希望按统一入口注册工具 | 由 ExtensionRegistry 登记名称、说明、参数 schema、执行器及版本并校验候选；普通重名或缺失执行能力阻止候选 generation 生效；显式替换需核对目标来源/版本及应用许可；AgentSession 在安全边界采用不可变实现快照，核心循环无改动 |
| TOOL-02 | 作为用户，我希望模型错误参数不会损坏数据 | 非法 JSON、必填缺失、类型/范围/枚举错误及多余危险字段均在副作用前处理；返回字段级原因，不替模型猜写入目标 |
| TOOL-03 | 作为应用开发者，我希望统一约束所有工具入口 | 主 Agent、子 Agent、工作流节点和直接 SDK 调用均经过同一策略语义；工具换名或被工作流包装不能扩大权限 |
| TOOL-04 | 作为用户，我希望明确知道哪些操作需要确认 | pre-execute 区分 allow/deny/cancel/ask；ask 只接受 allowed-once 批准，其他审批结果不执行；等待期间 Trace 为 waiting_input，重复回复不二次执行 |
| TOOL-05 | 作为使用者，我希望实时看到长工具进度和真实结果 | 开始、进度、结束均关联同一调用；非零退出码不得记为成功；晚到进度不改变已提交结果 |
| TOOL-06 | 作为用户，我希望取消和超时有可信含义 | 取消传播到工具及其子进程/子执行；确认停止后不再发起新工具；无法确定副作用时保留 `outcome_unknown`；没有取消意图时 Trace 为 `paused`，取消轨迹按 M03 收尾 |
| TOOL-07 | 作为编码用户，我希望并发调用不会互相覆盖 | 同一文件两次修改按声明顺序执行；未声明并发安全的工具默认串行；并行只读调用仍受并发数和资源预算限制 |
| TOOL-08 | 作为编码用户，我希望修改局限于当前沙箱许可范围 | write/edit 与 shell 文件修改采用同一解析策略和真实工作区/临时目录；越界按 DSH 式拒绝/单次升级处理；读取范围单独声明，工作区写限制不等于读取隔离 |
| TOOL-09 | 作为用户，我希望工具结果过大时仍可追查 | 模型正文包含有界预览、截断说明与实际可用续读入口；已有文件可按原资源续读，命令日志使用保存成功的产物；策略见 M08，二进制/图片按能力投影 |
| TOOL-10 | 作为扩展作者，我希望工作流和子 Agent 可组合 | 子委派与独立选择两种使用方式遵守相同权限与预算；独立方式主模型路由次数为 0；子执行不能写入另一顶层任务 |
| TOOL-11 | 作为用户，我希望工具失败可纠正而不是伪造成功 | 文件不存在、参数错误、编辑冲突等生成结构化失败反馈；重复失败受步骤预算约束；未知结果不自动重放 |
| TOOL-12 | 作为部署者，我希望编码能力跨环境可验证 | 四类环境分别运行路径、Unicode/空格、换行、命令退出、取消和文件冲突用例；不假设所有平台都有 Bash |
| TOOL-13 | 作为工具作者，我希望换执行环境不重写工具语义 | 相同定义经本地、受限后端及内存替身完成同一契约；所有实际效果使用注入能力 |
| TOOL-14 | 作为应用开发者，我希望后处理不篡改执行事实 | 可脱敏/缩减 content 与 details，但保留原结局和策略决定；拒绝/未知效果不能改为成功 |
| TOOL-15 | 作为用户，我希望许可与执行可追溯 | 审核/批准、sandbox mode/enforcement 和结果关联同一调用；所需审计提交失败时不执行 |
| TOOL-16 | 作为扩展作者，我希望按阶段开放已登记工具 | 实现/schema 固定于 generation，可见集合在 Turn 边界选择；调用绑定当轮选择，实际权限仍单独验证；选择及恢复可追溯 |

### 2.2 编码验证能力与非目标

已确认默认基础能力包含文件读取、限定编辑/写入、目录与内容查找、命令执行、TODO 及通用子 Agent；首个编码示例直接使用这套装配。创建入口必须提供与必需工作区对应的受控后端，缺失/不可用时明确报告装配失败。名称可随 Eino 适配确定，在 generation 内保持稳定；开发者显式裁剪的能力不向模型暴露，默认可见仍不代替逐次执行授权。

所有环境提供“命令执行”语义，具体 shell 由执行环境描述；结果包含 shell 类型、工作目录、退出信息和截断信息。Windows 原生不能用安装 Bash 作为未声明前提；容器采用其已配置的 shell，不假定镜像自带全部命令。

本章经 Operations/后端接入 DSH 方法的进程文件效果沙箱；不隔离同进程任意 Go 插件，也不自动限制所有网络访问。不做交互式终端产品，不承诺跨任意外部 API 的恰好一次执行或回滚。测试 Web 页面显示状态和回传审批，不拥有策略。

## 3. AI 系统要求与评测

### 3.1 可执行验收场景

以下场景使用临时仓库、内存工具、可控进程和假模型；不执行用户真实仓库命令或外部写 API。本轮为需求验收定义，不代表已有测试结果。

| 场景 | 注入条件 | 通过条件 |
| --- | --- | --- |
| T-E01 校验闭环 | 必填缺失、未支持的参数形式、越界参数、未知工具；另测允许的字符串数组规范化 | 无效输入执行为 0；已声明的规范化只有通过最终校验才执行，能指出失败字段 |
| T-E02 审批去重 | 写文件等待审批；响应重复提交，或审批过期后再次提交 | 有效批准最多执行一次；拒绝/过期不执行；等待期间同 Session 的其他顶层 Trace 不抢占写入 |
| T-E03 串并行 | 两读一写、同文件两写、未标记的自定义工具 | 冲突写入不重叠；未声明工具串行；只读并发不超预算；消息按原调用顺序提交 |
| T-E04 取消与超时 | 命令产生子进程；工具忽略 context；外部模拟操作已提交但返回丢失 | 能停止的执行确认退出；无法确认者标记未知并阻止普通继续；不能报告回滚成功 |
| T-E05 路径边界 | 写目标含 `../`、绝对路径、符号链接、junction、UNC、大小写/驱动器变化 | 按模式、平台和真实目标判定写范围；读取按独立规则，不假称工作区外一概不可读 |
| T-E06 编辑冲突 | Agent 读取后，人或另一进程修改同一文件 | 前置版本或旧内容校验失败；用户新内容不被静默覆盖 |
| T-E07 输出处理 | 工具输出大日志、密钥样本、二进制和最后一条晚到进度 | 模型上下文有界；敏感值不进普通事件/历史；产物可追查；终态不被更新覆盖 |
| T-E08 重试恢复 | 写工具完成后模型失败；审批后进程崩溃；恢复旧 checkpoint | 模型重试不再写；结果未知先核对；旧工具 generation 不可用时拒绝静默替换 |
| T-E09 组合入口 | 同一受限写操作分别由主 Agent、子委派和工作流独立 Agent 触发 | 策略一致，父子归属完整；没有“外层获批后内层任意执行” |
| T-E10 Operations 可替换 | 同一工具定义注入本地、沙箱、内存后端 | 参数与结果语义一致；工具无私自调用系统绕过后端 |
| T-E11 五步处理 | 规范化、校验、策略、执行、后处理分别注入错误 | 前三步失败实际执行为 0；普通错误可供纠正；安全/保存故障不继续副作用 |
| T-E12 结果双通道 | 大日志与结构化结果；后处理失败或改写权限结局 | content 有界，details 与原结局可追溯；不再执行已经成功的工具 |
| T-E13 动态工具选择 | 搜索后新增可见工具、批次内变更、retry/resume、明确权限撤销 | 普通变更在下一 Turn 生效；当前调用绑定旧选择；未知/越权不执行，恢复不默认开放全集；撤销仍有效 |
| T-E14 显式替换 | 同名普通登记、错误目标版本及允许的替换 | 前两者拒绝；允许替换形成候选版本，旧 Trace/审批不使用新执行器 |
| T-E15 授权描述一致 | 多个转换 hook 改参数、审批后改环境/参数、普通 hook 返回 allow | 最后转换后仍完整校验；执行描述改变则旧许可无效；allow 不绕过强制策略 |
| T-E16 运行数据与临时产物 | 文件/shell 访问可信状态路径；跨工具读取会话临时产物 | 受限模式阻止直接改写运行数据；同 Session 产物映射一致，后端私有临时文件不误读为宿主文件 |
| T-E17 默认基础能力 | 仅提供默认装配的必要输入，再分别调用文件、命令、TODO 与通用子 Agent | 真实能力及后端可用且受策略限制；缺后端明确失败，显式裁剪后只暴露保留工具 |
| T-E18 核对与恢复 | unknown 后查询状态/提交材料、重复请求及迟到相反材料 | 追加事实不重跑工具；人工标签不解除许可；冲突材料不覆盖已确认事实，恢复复用已有结果 |

### 3.2 模型反馈质量

每项工具说明应交代适用场景、必填字段、范围、输出和可恢复错误。参数错误反馈保留字段路径及修复条件；权限拒绝说明不可进行的操作，不诱导模型改名绕过。命令失败必须保留退出码与诊断摘要；工具自述“完成”不能覆盖执行器实际失败。

模型可以在收到失败后生成新调用，但新调用仍要重新校验和授权，并消耗步骤预算。连续同类错误的停止阈值由 Trace 预算统一约束，不增加一个与主循环互相独立的无限修复循环。

## 4. 技术契约

### 4.1 定义、调用和结果

以下字段为语义需求；最终 Go 类型及 wire schema 由开发方案确定。

#### 工具定义的三个层次

| 层次 | 可见内容与职责 | Eino 适配方向 |
| --- | --- | --- |
| L1 Tool 元信息 | name、description、schema、已认证的约束采样选项；不含执行器或页面组件 | schema.ToolInfo / tool.Info |
| L2 AgentTool 执行角色 | 元信息 + 参数规范化、执行、取消、进度、结果、并发声明 | BaseTool / InvokableTool / StreamableTool 等与统一管道；不重复整套 Eino 类型 |
| L3 ToolDefinition 应用角色 | 来源/版本、label、使用指引、窄业务上下文、后端与策略装配 | ExtensionRegistry 登记，创建时用包装器注入；展示只提供结构化资料 |

“已注册”“对模型可见”“本次允许执行”分别检查。登记证明能力存在，当前工具选择决定模型可见性，执行策略和沙箱决定实际操作。description/使用指引来自同一版本并保持稳定，配合 M04/M08 缓存；模型侧 strict schema 不替代本地调用校验。

#### 动态工具选择与实现版本

M11 定义登记/运行入口，本节定义执行语义。一个 Trace 固定工具实现、schema、说明及来源版本；本轮的可见工具集合属于执行状态，不等于更换 generation。

1. AgentSession 协调在首轮请求前或本轮工具批次结算后的下一 Turn 选择工具。候选必须来自该 generation 中本 invocation 获准使用的集合；拒绝未知名称、越权与跨版本选择，整体失败时保留原集合。多个请求按受理顺序处理，不并发改共享 map。
2. 同一 Turn 的模型 attempt、所产生的工具批次及未完成调用的审批恢复绑定同一选择和实现。普通选择变更只影响后续 Turn；不能在工具批次中途换掉执行器，也不能重新解释已接纳调用。当前权限撤销继续按安全规则拒绝后续实际启动或要求中止。
3. 工具搜索只检索当前候选。普通客户端搜索的新增可见工具在下一 Turn 开放；模型在同批次提前调用时拒绝。若启用已认证的供应商原生延迟检索，本轮清单同时记录普通工具与允许检索的延迟工具；仅可执行清单内、符合该协议检索/调用规则的工具，仍逐次授权。不能仅把任意名称塞进 ToolInfos 就视为可执行。
4. 工具选择与生效 Turn/invocation 一起记录；改变后更新 M08 工具说明、skill 加载能力清单、全量预算及 M04 缓存诊断。不承诺工具集合变化仍命中原缓存。
5. 重新构建执行实例或 resume 时恢复已生效集合及已受理待生效请求；不能回到所有工具默认开放。父子调用分别保存选择，子调用不扩大父任务授权；工具“可见”不等于“获准执行”。
6. 普通注册重名拒绝；明确替换要求目标存在且来源/版本匹配、应用允许替换。替换不能绕过统一校验、授权和结果处理；成功形成新的候选 generation，旧执行继续引用旧实现。基于已有执行器创建的配置化工具也遵循新能力登记边界。

Eino 的 BeforeAgent 可调整实际执行工具，BeforeModelRewriteState 调整后续模型可见 ToolInfos；两者不能混同。[源码](../../eino/adk/chatmodel.go#L386) `[VERIFY: eino/adk/chatmodel.go:386]`。toolsearch 提供 Agentic 泛型支持，[NewTyped](../../eino/adk/middlewares/dynamictool/toolsearch/toolsearch.go#L50) `[VERIFY: eino/adk/middlewares/dynamictool/toolsearch/toolsearch.go:50]`；原生检索能力与客户端回退分别认证，产品版本/权限/持久化保证由适配层补足。

#### 调用与结果记录

| 对象 | 最少内容 |
| --- | --- |
| 工具定义 | 稳定名称、说明、参数 schema、版本、执行能力、只读/有副作用标记、并发与资源声明、默认超时和输出限制 |
| 调用记录 | origin、Session、`toolCallId`、原始及规范化参数摘要、generation、策略版本、开始/结束；按来源关联实际 Trace/invocation/执行尝试或 operation；仅 model 必需 `turnId`、本轮工具选择引用和 providerCallId，workflow_node 保存定义/绑定及 nodeExecutionId，direct 保存受信入口能力 |
| 审批记录 | 唯一审批 ID、调用身份、规范化参数摘要、工作区/资源范围、generation、有效期及允许/拒绝响应；不得含明文密钥 |
| 结果 | 状态、模型内容、结构化数据或产物引用、错误分类、退出码、耗时、截断、已知副作用及取消确认；文件工具附可确认的文件操作事实与原调用关联 |

原始参数、业务转换后的候选和最终规范化参数可追溯；实际执行使用经最终校验和审批的同一冻结副本。冻结执行描述还关联工具/schema/generation、资源前提，以及适用的 argv/cwd/env 引用、环境与临时路径映射，详见 [M12](12-security-sandbox.md#411-参数转换完成后才冻结和授权)。schema、执行资源、环境或参数变化后旧批准无效；不能仅核对 toolCallId 或模型理由。

建议调用结果状态：`succeeded`、`failed`、`denied`、`cancelled`、`timed_out`、`outcome_unknown`。`waiting_approval` 是等待态，不是结果。状态表示执行观察结果；另记 `side_effect` 为 `none`、`confirmed` 或 `unknown`，因此“超时”不会被误读为“未发生任何写入”。

### 4.2 完整执行边界

按受信 origin 查找实现：model 使用产生该调用的 Turn/invocation/generation 和本轮工具清单，普通/原生延迟工具按上节区分；workflow_node 使用固定定义的本地绑定和 nodeExecutionId；direct 使用受信入口能力及已确定版本。三类都检查当前执行权限，再采用同一五步流程：

| 步骤 | 职责 | 退出行为 |
| --- | --- | --- |
| prepareArguments | 对完整参数做已声明的业务转换及兼容规范化；链结束后形成最终候选，保留原参数与变化来源，不执行工具 | 转换/规范化失败则停止；不改变原 toolCallId/工具身份或伪造批准 |
| validate | 对所有转换后的最终候选验证 schema + 业务前提，解析实际资源/执行环境并冻结执行描述 | 提前校验不能代替最终校验；model 返回配对错误结果，其他来源返回节点/操作错误，执行次数均为 0 |
| beforeToolCall / pre-execute | hook 只读冻结描述并提出决定；强制策略独立检查，完成必要审核、审批、审计和单次许可占用 | allow 不跳过强制检查；需要一次批准时先提交决定和占用，其余 allow 不额外询问；当前策略、取消与后端条件允许才继续 |
| execute | Operations/后端消费同一冻结描述及有效许可，启动前复核适用条件；分别记录启动事实、结果与取消 | 变化则停止并重新校验授权；占用不是 started，不确定是否启动/生效时进入核对 |
| afterToolCall / post-execute | 生成有界模型 content、结构化 details、产物与诊断；协调保存后封闭结果 | 不抹掉真实副作用、拒绝或审计；后处理失败不能重跑执行体 |

参数改写与授权分属不同阶段；安全决定处理器不再返回改写参数。若实现保留初步校验以便转换器读取，也必须在所有转换之后完成最终校验。冻结副本不与 hook 共享可变 map/slice；执行器不能通过重新解析全局默认值换掉已经审核的动作。pi 的可变 input 行为是参考差异，不作为本产品授权正确性的保证。

普通可修复错误（例如“offset 超过总行数”“旧文本与当前文件不匹配”）按来源返回：model 生成与原请求配对的 tool result，workflow_node 回填节点错误，direct 返回操作错误；后两类不制造模型消息。安全设施失效、审计无法提交、执行是否结束不确定等是停止/暂停条件，不能只反馈错误文字后继续危险动作。取消和人工等待不是普通重试错误。

content 是模型工作材料，details 保存状态、diff、路径、耗时和产物等结构化资料。后处理可修改脱敏后的投影视图，原执行事实和安全决定单独保留；details 不自动进入模型。历史、客户端和模型投影分别遵循 M06/M07/M08。

编码文件工具将操作类别（读取/写入/编辑）、规范化资源身份、可确认的效果状态及 toolCallId 放在原执行记录中，供 [M09 文件清单累积](09-compaction.md#34-文件记录由代码累积)复用。拒绝/未执行不记为成功修改，失败但已确认的部分写入仍如实保存，未知效果等待原调用核对。shell 和自定义工具只提供有证据的结构化文件信息，不从命令文本猜测，也不为压缩新增全工作区扫描；投影后处理不能覆写这些事实。

截断不能只在 details 留标记：模型正文按 [M08 截断与续读契约](08-context-engineering.md#42-工具输出截断说明与续读)提供范围、原因及可执行的下一步。read 头部、日志尾部、grep 单行和超长行处理各有规则；续读仍经过同一工具权限、范围和输出预算，不借 shell 示例绕过环境能力。

等待审批占用当前会话任务位置，按 M03/M10 恢复；重复批准不能重复执行。许可占用先持久提交再调用执行器，实际启动事件只在启动事实成立时发布；占用后缺少启动/结果记录不意味着可以再次使用，按 M12 的许可恢复表处理。已接纳进度先结算，再由 AgentSession 协调 SessionManager 保存并发布结果；迟到进度忽略。普通观察者失败不改变实际执行结局。

取消、超时与已发生副作用可以同时成立。用户 Abort 后不能把已经成功写入的文件虚构成未执行；无取消请求但无法确认外部结果时，Trace 为 `paused`，等待显式核对。有取消请求则先为 `cancelling`，确认执行停止后为 `cancelled` 并保留未知副作用记录，核对前禁止后续冲突操作。正常完成、失败、取消的终态不得通过普通恢复复活，详见[第 3 章](03-agent-loop.md)。

### 4.3 权限与环境

安全路线按用户要求参考 DSH：沙箱模式、审批策略、自动审核和审计记录独立，具体词汇与平台矩阵见[安全补充篇](12-security-sandbox.md)。应用装配方经 CreateAgentSession 注入默认组合，工具消费解析后的窄策略接口，不反向依赖 AgentSession/存储/HTTP。终端用户无需配置 runner 或审查提示词；审计、结果归属、去重仍是底座职责。

参考 DSH 文件效果模型，workspace-write 允许工作区与后端声明的临时目录内修改，read-only 禁止修改；直接文件 API 与 shell 采用同一策略来源。处理实际父目录、符号链接/junction、大小写和驱动器语义。读取本机可访问文件不由该写限制模式自动禁止；应用额外限制读取或网络时须独立声明。启用 skill 不增加权限。

进程沙箱使用 argv 和已解析策略，返回实际 full/partial 约束及失败原因；限制模式缺后端时拒绝，不回退裸命令。cwd 和字符串检查不是沙箱；容器需明确路径、挂载、网络及凭据，不能只更换 runner 就宣称全隔离。

同进程 Go 扩展属于可信代码。工具权限限制面向注册调用路径，不能阻止插件直接调用操作系统；需要不可信扩展时另立隔离执行需求，不通过本章策略接口假装已解决。

### 4.4 并发、取消与不确定结果

拟定默认采用串行派发；只有同时满足“显式声明可并发、无资源冲突、预算允许”的调用可以并行。缺失并发声明不按只读推测。路径写入与 shell 默认有副作用；同一批中出现未知资源副作用时，整批保守串行，避免推测命令访问范围。

执行次数、并发数、超时和取消确认窗口由底座提供默认策略，开发者后续通过代码装配调整；终端用户无需配置这些运行参数。该边界不替代用户对具体工具操作的审批语义。

并行完成事件按真实时间出现，结果消息按原调用顺序形成闭合批次；跨调用的完成顺序不能用来关联结果。并行工具中出现审批暂停时，已开始的兄弟调用要收敛并记录完成或未知状态；恢复不得重复执行这些已经完成的调用。

工具超时与取消必须向执行器传播并有明确的确认窗口。若执行器不合作，普通 Go context 不能保证任意代码已经停止；应将调用标记未知、阻止该 Session 继续冲突操作，并要求执行环境核对/终止。具体确认窗口默认值待定。

Eino 并行路径启动 goroutine 后等待全部完成；它本身不等价于不合作工具的硬终止器。见 [parallelRunToolCall](../../eino/compose/tool_node.go#L985)。[VERIFY: eino/compose/tool_node.go:985] 取消本机 shell 时还要验证后代进程退出；pi 的本机 bash 实现显式处理进程树和 AbortSignal，见 [取消处理](../../pi/packages/coding-agent/src/core/tools/bash.ts#L118)。[VERIFY: pi/packages/coding-agent/src/core/tools/bash.ts:118]

对于“外部操作已完成，但返回或结果持久化丢失”，仅凭 checkpoint 不能推断是否可再执行。结果必须为 `outcome_unknown`；有业务幂等键或状态查询接口时可由核对操作确认结果，否则要求人工核对。工具不得默认自动重试，幂等工具的可重试范围必须显式声明并纳入预算。

吸收 pi 的“顺序准备 → 并发执行 → 有序归并”，一个被拒调用不必然取消所有无关兄弟调用；任务取消或安全设施故障则按整批规则收敛。文件后端另做真实资源键串行与版本检查，避免仅凭工具名猜冲突。

pi terminate 要整批所有 finalized 结果都要求停止才使该批工具不再驱动下一轮；随后仍执行轮后钩子，并按 M03 检查 steering/follow-up。[批次判断](../../pi/packages/agent/src/agent-loop.ts#L582) `[VERIFY: pi/packages/agent/src/agent-loop.ts:582]`；[轮后处理](../../pi/packages/agent/src/agent-loop.ts#L224) `[VERIFY: pi/packages/agent/src/agent-loop.ts:224]`。它不是任一工具喊停即取消整个 Trace，也不能等同于 pigo 的直接收尾或 Eino return-direct。普通权限拒绝可反馈模型，不借 terminate 伪造 completed。

#### 核对未知执行效果

核对由 AgentSession 协调，入口和幂等要求见 [M07](07-events-and-access.md#核对操作的语义)。目标是已有的 invocationId/toolCallId 及许可占用记录；使用 operationId 关联核对，不生成新的业务工具调用或模型 Turn。

1. 可发起应用提供的受控只读状态查询，或提交人工材料/已存在产物引用。查询沿用权限、作用域和后端约束，不能接收任意 shell 字符串充当核对，也不能重跑原操作来探测结果；没有可靠查询能力就明确报告需补证据。
2. 原执行尚未确认停止、外部请求仍可能继续生效时，当前快照不能证明“最终未执行”；可检查/收敛执行状态，但结论仍保持未知。核对不承诺强制终止不合作的 Go 代码。
3. 服务端区分材料来源与可确认结论：受信后端/业务查询的证据、人工陈述、确认过的完整/部分效果及仍未知部分分别保存。人工选择“未执行”不是受信启动证明，不能直接解除一次许可或伪造成功。经应用规则核验的人工材料可确认特定当前业务状态；历史调用是否执行过与当前资源冲突是否已解除分别判断，不能把两者合成一个“核对成功”布尔值。
4. SessionManager 追加核对事实后才更新有效工具视图和资源冲突限制。已确认结果在恢复中复用，不能因新 executionId 再执行；若无法可靠承接已有结果，则不标记可恢复。
5. 对 cancelled/failed Trace 可继续澄清历史效果，但不改变其终态。对 paused Trace，仅在副作用冲突、许可与 checkpoint 条件均满足后允许显式 resume；核对成功本身不触发执行或旧队列继续。

具体证据如何证明某项外部效果由对应工具/业务适配器定义；不要求每个工具都新增接口，不新建通用审判系统。缺少可靠证据时保留 unknown 和冲突限制，不能为了让会话继续而清空它们。

### 4.5 Operations 与执行后端

工具只依赖所需的读取/修改/搜索/命令能力；Operations 不持有 AgentSession 或前端连接。创建工具时注入实现，能复用 Eino filesystem.Backend/Shell 的部分直接复用，只补实际缺少的适配。

同一工具可换本地、沙箱、容器或测试替身，但文件系统、命令、路径解析与沙箱必须处于同一个执行环境。会话产物目录在这些入口映射到同一真实位置，后端私有 tmpfs 的路径不冒充可续读产物；需要保留时先导出保存。不能 read 读取容器文件、shell 却在宿主同名目录操作；也不能只包住辅助进程，实际修改仍在宿主旁路进行。

运行数据根与业务可写根按 M12 分离并验证保护；仅仅将日志/checkpoint 放到另一个路径不代表沙箱已禁止写入。直接文件工具与进程后端都需通过相应保护和临时产物验收。

受信工具的路径写入检查与不受信命令的 OS 约束分开实现，参考 DSH fs-sandbox 和 process sandbox 的分工。审批批准操作，后端落实约束，不能互相替代。

### 4.6 产物、工作流与子 Agent

工具正文与元数据分离：给模型的是经限制的内容，给客户端的是产品事件，完整日志/大文件是可访问的产物引用。产物的权限、保留、清理与 Session 生命周期由[第 10 章](10-session-persistence.md)统一规定；重连不要求重跑工具才能重新拿到结果。

工作流两种使用方式共享本章约束：作为子 Agent 委派、作为对话框选择的独立 Agent。独立方式仍占用 Session 的顶层 Trace，输入来自用户也必须校验；工作流内部节点权限由实际副作用判断，不能只在外层名称处批准一次。不提供第三种 workflow-as-tool 产品入口。

统一管道区分受信建立的调用来源：模型工具调用检查本轮可见性；工作流工具节点检查固定定义的本地绑定；直接命令/获准 SDK 调用检查受信入口能力。三者均经过最终参数校验、冻结、授权、预算、许可与效果去重，不能由客户端自填来源绕过。无模型的工作流节点以 invocation/nodeExecutionId 关联稳定产品 toolCallId，不要求或伪造 Turn/providerCallId，也不借用父 task 的 Turn。节点结果回填节点状态，不制造 FunctionToolResult；子委派外层仍只向父 task 返回其配对结果。

子 Agent 保留父 Trace、独立执行路径和自身模型/工具事件；它不能消费顶层 steering 队列或直接提交主 Session 历史。权限、预算和可用工具不超过父级授权；完成后通过父调用结果归并。包含 HITL 的工作流/子 Agent 还必须满足原 generation 的恢复契约，不能只有 Run 没有恢复语义。
